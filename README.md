# 链上观察：第一版

## 当前已连接状态（2026-09-10）

Supabase 数据表和权限已初始化，管理员 `admin` 已创建。现在登录使用「账号 + 密码」，不用真实邮箱或邮件验证。底层 Auth 使用内部占位地址，用户无需填写或了解这个地址。下面旧的手工邮箱配置步骤仅供维护参考。

管理员初始密码只在 `.local-accounts/admin.txt`，此目录已被 Git 忽略。当前访问地址为 `http://localhost:5173/`，只在这台电脑的预览服务运行时可用，还不是手机可访问的正式网址。

需要分发一个普通账号时，在应用目录运行：

```sh
node scripts/create-account.mjs member01 member
```

账号为 3–32 位字母、数字、下划线或短横线。该命令生成随机密码，创建已确认的 Auth 用户和成员权限，不发送邮件；密码存入 `.local-accounts/member01.txt`，由管理员自行交付。已有账号不会被覆盖；只有上次中断且保留密码文件时才使用 `--resume` 核对并继续。不要把普通成员创建为 admin。成员自行登录后可点击「改密」。

已用真实项目验证公共列表读取、管理员登录、会话续期、退出和匿名添加拒绝。没有为测试写入虚构币种。正式分享部署、手机访问和浏览器完整操作流程仍需后续验证。

已执行 `supabase/002_edit_delete.sql`：取消归档入口，旧归档记录恢复显示；管理员通过每行末尾「…」编辑收录信息或确认删除。删除移除公共记录和对应收藏，重新添加视为新收录。首次市值支持 K/M/B/USD，默认 K；时间未修改时使用提交时刻，自定义时间不自动查询历史行情。

本版实现「公共列表每 30 秒检查版本，行情由每位访问者的浏览器每 60 秒直接向 DEX Screener 查询」。行情不经过数据库且不存 Supabase；无人打开时不运行采集。没有 Supabase 配置时显示真实的待配置状态，不保存模拟公共记录。

## 1. 创建 Supabase 项目

1. 在 Supabase 控制台创建项目，选择你访问较稳定的区域，保存数据库密码。
2. 打开 SQL Editor，按编号依次执行 `supabase/001_watchboard.sql` 到 `supabase/004_price_baselines.sql`。001 只在新项目执行一次，已有安装只执行尚未应用的增量迁移。
3. Authentication 设置中关闭公开注册。Users → Add user，创建邮箱/密码用户，勾选邮箱已确认（无需默认 SMTP 发送邮件）。每个人一个账号。
4. 从 Users 复制用户 UUID，执行以下 SQL。先把示例 UUID 换成自己的真实用户 ID，不要照抄示例 ID。

```sql
insert into public.members(user_id,role)
values ('11111111-1111-4111-8111-111111111111','admin');
-- 其他用户使用 role='member'。
```

5. 将临时密码通过自己的渠道交付成员，首次登录后点击「改密」设为至少 12 位密码。忘记密码由管理员处理；自助邮件找回需要另配 SMTP，本版不伪装提供该能力。

## 2. 连接应用

从项目 API 设置取得项目 URL、公开 anon/publishable key，以及 **server-only Secret key（sb_secret_ 开头）**。服务密钥仅供后端取基准和事务收录，绝不能放进前端、提交 Git 或发送聊天。

本地在应用根目录创建 `.dev.vars`（已忽略），按 `.env.example` 的三个变量填写。服务器运行在 Cloudflare Workers；部署时将这三个变量填到托管平台的服务端 Secrets。不要使用 NEXT_PUBLIC_ 前缀。客户端不会收到密钥，后端不打印密钥。

本应用目前使用 Supabase HTTP Auth/REST API，不要求安装 Supabase CLI，也没有直连 TCP 数据库。

```sh
npm run install:ci
npm run dev
```

打开启动命令给出的本地地址。未配置时添加按钮禁用；配置后重启预览。使用刚创建的账号登录并添加一个 CA，另一个账号打开后应在 30 秒内同步列表，收藏彼此独立。

本机 npm 启动器若异常，可用 `node "C:/Program Files/nodejs/node_modules/npm/bin/npm-cli.js" run dev`。

## 3. GitHub 与 Cloudflare 自动部署

代码使用 GitHub 私有仓库管理，生产分支为 `main`。Cloudflare Workers Builds 连接该仓库后，每次推送到 `main` 都会自动构建并发布；其他分支可按需开启预览版本。

Cloudflare 构建设置：

- Production branch：`main`
- Build command：`npm run build`
- Deploy command：`npm run deploy`
- Non-production deploy command：`npm run deploy:preview`
- Root directory：仓库根目录

在 Worker 的 **Settings → Variables & Secrets** 中添加 `SUPABASE_URL`、`SUPABASE_ANON_KEY`、`SUPABASE_SECRET_KEY`，类型均选 Secret。它们属于运行时配置，不要填进 GitHub 文件或 Cloudflare 的 Build variables。`.dev.vars` 只用于本机且已被 Git 忽略。

首次发布后验证登录、列表读取、添加与删除、收藏、行情和历史估算。以后在其他电脑克隆仓库、创建自己的 `.dev.vars`、执行 `npm ci` 即可继续开发；提交并推送 `main` 后 Cloudflare 自动更新正式网址。

## 4. 行为和限制

- 历史估算使用 GeckoTerminal 免密钥公共 API。修改收录时间后停输 800ms 查询分钟线；只取目标时刻之前已结束、有成交且结束时间距目标不超过 120 秒的分钟线，不插值到秒。当前候选池按流动性选取且必须在目标时刻已建立，无法覆盖迁移前旧池或未被返回的历史池时须手填。分钟线收盘价同时保存为公共首次币价。
- 估算公式：历史分钟收盘价 ×（DEX Screener 当前市值 ÷ 当前价格）。这是供应量不变假设下的估值，不是历史供应量实测；不使用 FDV 替代缺失市值。每次成功查询一般 2 次 GeckoTerminal 请求、1 次 DEX 请求，Supabase 仅校验成员，点击保存才写入估算依据。无需 OKX 凭证或持续采集。
- 手填金额不被历史查询覆盖，可点击「使用此估算」。修改地址、链或时间会使之前的估算失效。自定义时间且金额留空时保存为暂无基准，不再自动取当前市值。列表标注「历史估算 · 1分钟」，估算元数据随公共记录保存。
- 新安装依次执行 001、002、003、004 SQL。004 增加公共首次币价和按账号隔离的个人入场价；已有历史估算记录会从估算元数据回填首次币价，无法可靠恢复价格的旧记录保持空白。

- 添加时粘贴完整 CA，停输 500ms 自动查询 DEX Screener 搜索接口。仅保留当前支持网络的完整地址匹配结果，按链合并交易池；单个候选自动选择，多个候选由用户确认。换 CA 清空旧选择；无结果或失败可手动选链。搜索结果不保证覆盖所有网络，仍保留手动入口。
- 匹配仅查询候选，不写数据库；需要有效成员登录，涉及会话和成员权限读取。确认添加时重新获取当时行情，沿用同链去重。候选仅作为报价资产出现时不使用交易对另一币种的市值。

- 支持 Ethereum、BSC、Base、Solana、Robinhood 的入口；具体 CA 仍依赖 DEX 收录。Robinhood REST 真实 CA 尚未获得样本验证，不能保证任意新币都有数据。
- 点击列表中的 CA 可选择复制完整地址，或在新标签打开该链对应的 GMGN 代币页。
- 当前倍数按币价计算。未设置个人入场价时使用公共首次币价；登录用户可为每个币保存自己的美元入场价，设置后倍数显示和排序优先使用个人价格。个人入场价仅本人可见，可随时清除。
- 同链 CA 唯一，EVM 小写，Solana 保留大小写。重复提交保留已有时间和基准；管理员可另行编辑。手填市值按所选 K/M/B/USD 换算为美元后优先采用，空白读取添加当时可取得的数据。未调整时间时使用服务器提交时间。
- 缺市值可收录为暂无基准，不用未来市值回填；市值与 FDV 不混算。选匹配 baseToken 的深池，记录基准来源池。
- 普通成员添加和收藏，管理员在每行末尾「…」编辑收录时间、首次市值或确认删除。删除同时清除对应收藏，审计记录保留。首期最多 300 个合约。
- 浏览器持有行情，并直接请求 DEX Screener；隐藏标签页暂停发起新批次，已在途请求可能完成。恢复时查询受至少 60 秒请求间隔保护。
- 搜索与排序在浏览器进行，数据库只在列表版本变化时重读列表。登录状态/收藏在打开、返回页面及会话续期时重读，收藏不同设备不会实时推送。
- 同一浏览器多标签各自轮询，建议只保留一个可见看板窗口；本版未做跨标签选主。数据源限流时遵守 Retry-After，保留旧行情，在底部显示冷却倒计时并自动重试；查询恢复后提示自动消失。
- 不记录无人查看期间最高倍数、K 线或提醒。数据时间标记是抓取时间，不是行情源对最新成交的保证。
- Worker 的旧 `/api/quotes` 代理暂时保留一个发布周期用于快速回滚，正常页面不再调用。添加合约和历史估值仍会由 Worker 发起少量行情请求。

## 5. 免费容量重新核算

数据库部分只检查版本、初次/变更读取公共列表、登录和收藏。没有 quote_cache、quote_batches 或刷新租约表。

持续行情不再计入 Worker 请求量。DEX Screener 仍按链每批最多 30 CA，但请求由各访问者的浏览器直接发出。

| 模型：15 人在线 | Worker 行情请求/日 | 列表版本请求/日（8h） | 列表版本请求/日（24h） |
|---|---:|---:|---:|
|100–300 币、五条链|0|14,400|43,200|

按 Cloudflare Free 100,000 请求/日计算，15 人全天挂着的列表版本检查约 43,200 次；额外登录、首次/变更列表、添加和历史估值仍要计入，但持续行情不会占用 Worker 请求额度。

DEX 上游在 100/300 币、五条链模型下总计约 75/150 次每分钟，但会分散到 15 位访问者；单个浏览器约 5/10 次每分钟，低于文档 300 次/分钟。仍须遵守供应商动态限流和 Retry-After。CPU 10ms 的免费限制仍须真实 Cloudflare 环境验证，本地测试不能证明满足。当前框架是 Sites 的 React/Vinext（Vite + Worker）脚手架，部署成本以实际 Worker 用量为准。

## 6. 测试与运维

```sh
npm test

```

自动测试覆盖数据库 SQL/RLS、跨链去重、自定义时间、单位换算、管理员编辑/删除权限、删除收藏清理、重新收录、行情许可、跨域写入拒绝、缺市值和429。旧版基准保护与归档测试仍用于验证 001 迁移基础。数据库测试使用本地 PostgreSQL PGlite，不等同于生产验收。

每周备份 tokens、favorites、members、board_state、audit_log；CSV 不包含 Auth 用户与密码哈希，完整身份迁移须遵循 Supabase 官方备份/恢复流程，保持收藏 user_id 对应。至少月度验证一次恢复，不能仅导出就声称可恢复。免费 Supabase 闲置一周可能暂停，需控制台恢复；不靠定时保活规避。持续关注数据库大小、出站流量、Worker 请求和 CPU。
